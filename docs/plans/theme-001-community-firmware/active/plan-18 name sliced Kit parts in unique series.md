# Name sliced Kit parts in unique series

## Purpose

Give generated Slice and Manual slice rows stable names such as `A-01`, then use the next series for later slice batches so they cannot collide with existing Kit-row names.

## Product integration

- Existing model: generated slices receive simple numeric names. Reusing a Kit can therefore create ambiguous or colliding labels.
- User intent: make every new slice batch easy to recognize, distinguish, and manage in a growing Kit.
- Integrated model: a first generated slice batch uses `A-01`, `A-02`, and onward. Before each later batch, the Kit detects earlier generated series and assigns the next series marker, such as `B-01`, `B-02`.
- Architecture impact: centralize the generated-slice naming decision at the point where Slicer commits a new batch, after considering current Kit rows and before assigning their visible names.
- Existing behavior preserved: a row's sample contents, slice boundaries, note data, placement, and playback remain unaffected by its new label.

## Scope

- In scope: name rows generated by Slice and Manual slice in alphabetical series with a zero-padded numeric part number; detect prior generated series in the current Kit; choose a later unused series so newly generated labels are unique.
- Keep stable: manually named rows, source filenames, slice contents, slice ordering, placement, Sound Drum settings, project save format, playback, manual slicing controls, and all unrelated sample-browser actions.
- Out of scope: renaming existing rows, applying the convention to Load all, changing filename handling, a global Kit naming scheme, hardware flashing, installation, release publication, or upstream submission.

## Completion Criteria

- [x] The first Slice or Manual slice batch in a Kit receives `A-01`, `A-02`, and onward.
- [x] A later generated batch detects the existing series and receives the next series, such as `B-01`, without colliding with existing names.
- [x] Series allocation remains deterministic when a Kit has manually named rows or prior generated batches.
- [x] Generated labels support more than two digits without truncating or repeating a name.
- [x] `DEVIATIONS.md` describes the naming contract and collision boundary without source-level instructions.
- [x] Focused review, host checks, and a local Nix Release build pass. No flashing or publication occurs.

## Decisions

- **Decision:** Use one alphabetical marker per generated batch and a numeric part number within that batch.

	- **Rationale:** `A-01` groups related slices while making a later `B-01` batch visibly distinct in the Kit list.

- **Decision:** Preserve existing labels and select a new series rather than rename previous rows.

	- **Rationale:** Existing names may carry player intent. Avoiding a collision is safer than normalizing a Kit the player already organized.
